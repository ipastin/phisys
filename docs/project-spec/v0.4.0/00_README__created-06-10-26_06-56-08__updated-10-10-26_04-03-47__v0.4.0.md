# MyPhisys — Project Specification Pack v0.4.0

## 1. Назначение пакета

Этот пакет — единый source of truth для проектирования и реализации **MyPhisys — Personal Health Intelligence System**. Он заменяет разрозненные решения из рабочих обсуждений и предназначен одновременно для:

- владельца продукта и Product Designer;
- AI coding agents (Codex, Claude и аналогов);
- будущего engineering/clinical/security review;
- фиксации архитектурных решений и границ безопасности;
- контроля scope MVP → V1 → V2.

Система **не проектируется как AI Doctor**. Её продуктовая роль: строить структурированную longitudinal model здоровья, выявлять достоверные изменения, показывать provenance, объяснять контекст и помогать готовить следующие действия/вопросы без автономной диагностики или изменения лечения.

## 2. Brand & product formula

> **MyPhisys is a Personal Health Intelligence System that continuously builds a trustworthy longitudinal model of health and helps the user understand what changed, why it may matter, what remains uncertain, and what may be useful to discuss or do next.**

Core loop:

```text
Health data
  → Canonical Health Store
  → Deterministic Analytics
  → What Changed?
  → Context
  → Safety Policy
  → AI Explanation
  → User action / review / record
```

Главная архитектурная формула:

> **Deterministic first → generative second.**

## 6. Архитектурные pillars

1. **FHIR-independent canonical model.** FHIR R4/R4B — adapters/interchange, а не внутренняя domain model.
2. **PostgreSQL — system of record.** Vector store не является Clinical Memory.
3. **Raw / Canonical / Derived / Inferred** физически и семантически разделены.
4. **Provenance first.** Каждый persistent clinical fact прослеживается до источника.
5. **Typed memory.** Нет универсальной agent memory.
6. **Bounded hybrid agent.** Workflow-first, planner только для composite requests.
7. **Safety control plane.** Authorization и clinical policy находятся вне LLM.
8. **Metric-aware analytics.** Одинаковые алгоритмы не применяются ко всем health metrics.
9. **Insight-first UX.** Home = Today / What Changed, а не blank chat.
10. **Source-independent tools.** Agent не знает Health Connect/HealthKit specifics.
11. **Health Connect first.** Android — первая real-data platform.
12. **Modular monolith first.** Microservices/Kubernetes исключены из MVP.
13. **Core works without LLM.** Records, Timeline, trends и What Changed не зависят от model availability.
14. **AI inference never becomes Clinical Truth automatically.**
15. **Unknown stays unknown.** Missing data не трактуется как zero/normal/negative.
16. **Capability-based model routing.** Application code requests logical capabilities, never production model IDs.
17. **Privacy before provider selection.** Model availability never expands allowed health context; fallback may degrade functionality but not privacy guarantees.
18. **Hub-and-spoke delivery.** Mobile is the primary hub; web, ambient and external surfaces have explicit constrained roles instead of feature parity.

## 7. MVP product scope

### Входит

- Android + Health Connect;
- Sleep, Steps, Heart Rate/Resting HR, Weight;
- manual observations и symptom logging;
- PDF laboratory import;
- HbA1c / lab history;
- Today;
- What Changed?;
- Insight Detail;
- Metric Detail;
- Timeline;
- Records;
- scoped Ask MyPhisys;
- lab/change explanation;
- provenance/context inspection;
- safety policy;
- export/delete.

### Не входит

- iOS HealthKit;
- SMART on FHIR / EHR direct connection;
- Health Connect Medical Records;
- direct Garmin/Oura/Fitbit APIs;
- MCP exposure;
- forecasting;
- brute-force correlations;
- autonomous diagnosis;
- treatment/dose changes;
- family profiles;
- provider messaging.

## 9. MVP success criteria

MVP считается пригодным для Personal Beta только если одновременно выполняются:

- canonical clinical facts имеют provenance;
- deterministic calculations reproducible;
- RLS/person isolation проходит тесты;
- treatment-modification capability отсутствует;
- critical authorization bypass = 0;
- critical prompt-injection success = 0;
- numeric golden tests = 100%;
- imported clinical facts traceable to original source;
- false-insight rate измеряется;
- unsupported substantive clinical claims ≈ 0;
- user может экспортировать и удалить свои данные.

## 10. Working mode
