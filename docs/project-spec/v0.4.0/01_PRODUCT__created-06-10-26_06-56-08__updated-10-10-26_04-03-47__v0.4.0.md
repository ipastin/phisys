# Product Specification

## 0. Brand positioning

**MyPhisys** is the single product brand.

- Category: **Personal Health Intelligence**
- Tagline: **Your health, understood.**
- Product line: **Understand your health over time.**
- Core interaction: **What Changed → Explore → Ask MyPhisys**

Positioning shorthand:

> **MyPhisys turns fragmented health records, measurements and everyday health data into a trustworthy longitudinal picture of your health.**

## 1. Vision

Создать MyPhisys — персональную Health Intelligence System, которая непрерывно формирует доверенную longitudinal model здоровья и помогает отвечать на три вопроса:

1. **What is happening?** — что сейчас известно о моём состоянии;
2. **What changed?** — что изменилось относительно моего недавнего personal baseline;
3. **What deserves attention?** — какие изменения достаточно устойчивы/значимы, чтобы их изучить или обсудить.

Продукт не конкурирует с врачом и не маскируется под medical authority. Его сильная сторона — объединение fragmented personal data, longitudinal reasoning, provenance и explainability.

## 2. Positioning

Не использовать позиционирование:

- AI doctor;
- autonomous clinician;
- diagnostic assistant for consumer self-diagnosis;
- treatment optimizer.

Использовать:

- Personal Health Intelligence;
- longitudinal health understanding;
- evidence-aware health record companion;
- personal health operating system с агентным слоем.

## 2.1 Delivery positioning

MyPhisys is not delivered as one universal screen everywhere. It uses a hub-and-spoke product model:

```text
Mobile = understand + act
Web = investigate + organize
Widget/Push = notice
Watch = glance + capture
MCP/API = integrate
```

Personal Beta is Android-first. Responsive web is the first companion surface; widgets/notifications follow after the core mobile value loop is validated. iOS/HealthKit and watches are later platform expansions.

The product explicitly rejects cross-platform feature parity when a surface is a poor fit for a job. See `17 SURFACE_STRATEGY`.

## 3. Product principles

### Facts before interpretation
Сначала deterministic observations/changes, затем AI explanation.

### Signal over volume
Не максимизировать количество cards/alerts. Допустимый результат — `No meaningful changes detected`.

### Personal baseline before judgement
Personal baseline описывает привычный диапазон пользователя и не называется clinical normal.

### Unknown stays unknown
Недостаток данных обязан быть виден пользователю.

### Source always reachable
Любой существенный clinical fact можно trace до source.

### Calm by default
Не усиливать health anxiety красными warning-state без policy основания.

### Inspectable AI
Пользователь может увидеть categories personal context и sources, использованные AI.

### Action conservatism
Read freely → analyze deterministically → recommend carefully → write with confirmation → treatment actions unavailable.

## 4. Core JTBD

### JTBD-01 — Understand
Когда появляется новый результат, пользователь хочет понять его в контексте своей истории, а не получить generic справку.

### JTBD-02 — Monitor
Пользователь хочет знать, какие показатели действительно изменились, без чтения десятков charts.

### JTBD-03 — Explain
Пользователь хочет увидеть возможный контекст изменений с явным различением association и causation.

### JTBD-04 — Remember
Система должна помнить проверяемую longitudinal history так, чтобы пользователь не восстанавливал даты/значения вручную.

### JTBD-05 — Prepare
Перед визитом система собирает changes, symptoms, meds, labs, questions и provenance в appointment brief.

### JTBD-06 — Track
Пользователь легко записывает symptoms/manual measurements; conversational input всегда проходит structured preview.

### JTBD-07 — Plan
Health goals существуют отдельно от clinical targets и поддерживают user-controlled planning.

### JTBD-08 — Watch
Пользователь может opt-in на события вроде нового результата или meaningful personal change. Watch не равен emergency monitoring.

## 5. Three agent modes

```text
ASK    — user initiated
REVIEW — scheduled structured review
WATCH  — event/rule initiated, opt-in
```

MVP сфокусирован на `ASK` + `What Changed`; `REVIEW/WATCH` расширяются позже.

## 6. Product boundaries

### Система может

- import и normalize data;
- показывать Timeline/Records;
- считать baseline, delta, trend, data quality;
- строить Health State Snapshot/Diff;
- surface meaningful changes;
- объяснять медицинские термины/результаты с evidence;
- показывать hypotheses как hypotheses;
- готовить вопросы/brief;
- записывать user-reported symptom/measurement после подтверждения.

### Система не может автономно

- поставить окончательный диагноз;
- начать/остановить medication;
- изменить dose;
- заменить medication;
- выдавать correlation за causation;
- скрыть missingness/conflict;
- отправлять health data external recipient без preview/approval;
- сохранять AI inference как verified clinical fact.

## 7. Product architecture of value

```text
Sources
→ trustworthy history
→ personal baseline
→ meaningful change
→ context
→ explanation
→ next useful action
```

Продуктовая ценность возрастает слева направо, но доверие определяется качеством первых четырёх шагов.

## 8. Killer feature — What Changed?

`What Changed?` — central product mechanism, а не LLM prompt.

Пользователь видит:

- meaningful changes;
- new clinical events;
- stable domains;
- data gaps;
- nearby events/context;
- quality/provenance on drill-down.

LLM появляется только на этапе explanation.

## 9. North-star product metric

Не `messages/day` и не `time in app`.

### Health Understanding Rate
Доля meaningful health events, которые были:

1. корректно структурированы;
2. корректно рассчитаны/сопоставлены;
3. представлены с provenance;
4. объяснены на нужном уровне uncertainty.

Supporting metrics:

- Data Completeness;
- Record Correctness;
- Insight Precision;
- Citation Support Rate;
- False Insight Rate;
- User Correction Rate;
- Context Precision;
- Unnecessary Anxiety / false-alert rate.

## 11. V1 priority

Предварительный порядок после Personal Beta:

1. Appointment Prep;
2. Medication + Conditions;
3. Weekly Review;
4. Health Connect Medical Records / FHIR;
5. Watch;
6. constrained Correlation Engine;
7. HealthKit;
8. MCP read-only adapter.

## 12. V2 candidates

- direct wearable APIs при доказанном data gap;
- advanced longitudinal reasoning;
- metric-specific anomaly models;
- validated forecasting только для подходящих metrics;
- richer care-plan support;
- scoped external provider workflows;
- local/private model routing;
- family profiles только с отдельной security architecture.

## 13. Product anti-goals

- universal health score;
- endless AI-generated insights;
- engagement loops вокруг тревожности;
- alerting на каждое отклонение;
- generic symptom checker как primary product;
- shiny multi-agent architecture ради demo;
- AI-first UI без deterministic core.
