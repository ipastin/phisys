# Health Intelligence & Analytics

## 1. Role

Analytics Engine — вычислительный слой между Canonical Store и AI. LLM не получает raw time series для самостоятельного подсчёта trends/baselines.

```text
Canonical observations
→ metric profile
→ quality gate
→ baseline/trend/state diff
→ meaningfulness
→ InsightCandidate
→ AI explanation (optional)
```

## 2. Metric Registry

Каждая metric имеет typed definition:

- concept;
- measurement class;
- temporal class;
- canonical unit;
- aggregation policy;
- baseline policy;
- trend/variability policy;
- quality policy;
- interpretation policy.

Measurement classes:

```text
direct_measurement
laboratory
device_derived
questionnaire
user_reported
calculated
```

Temporal classes:

```text
sparse
episodic
daily
continuous
event
interval
```

## 3. Source/method segmentation

Device/source/method transitions являются analytical events. Нельзя слепо сшивать серию при смене устройства/метода.

Strategies:

- merge — compatible;
- segment — possible measurement shift;
- parallel — semantically distinct sources.

## 4. Series Quality

Каждая analytical output включает:

- coverage;
- sample count;
- freshness;
- regularity when relevant;
- source continuity;
- duplicates/invalid points;
- source transitions;
- `sufficient / limited / insufficient`.

No analytics claim without quality gate.

## 5. Missingness

Canonical observations не interpolated.

Interpolation допустима только как derived visualization/signal-processing artifact и всегда маркируется.

## 6. Baseline semantics

Разделять:

```text
Population Reference Range
Personal Baseline
Clinical Target
User Goal
```

### MVP baseline для dense daily metrics

- robust rolling median;
- dispersion via MAD/IQR;
- baseline window lagged относительно current evaluation window;
- minimum-data requirement.

Пример engineering default:

```text
baseline = preceding 28 days
current = last 7 days
```

Это не clinical threshold.

## 7. Baseline contamination

Current shift не должен быстро «обучить» baseline на собственном отклонении. Current window исключается из reference window.

## 8. Trend

Trend output:

- current;
- previous/baseline;
- absolute delta;
- relative delta;
- slope where valid;
- direction: increasing/decreasing/stable/uncertain;
- period;
- sample count;
- quality.

Не использовать `improving/worsening` как default analytics semantics.

## 9. Sparse labs

Для HbA1c/LDL/etc:

- 2 points = delta;
- 3+ points могут дать trajectory при достаточной temporal relevance;
- interpolation запрещена;
- generic personal range обычно отключён.

## 10. Variability

Generic robust primitives:

- MAD;
- IQR;
- optional SD/CV для подходящих metric profiles.

Average без variability часто недостаточен.

## 11. Change detection

MVP — robust rule-based persistent shift, не ML-first.

Candidate change проходит:

```text
magnitude
+ persistence
+ data quality
+ source continuity
```

Single anomaly не превращается в meaningful change автоматически.

## 12. Association / correlation

**Не входит в MVP.**

V1 design:

- hypothesis-constrained metric pairs;
- context profiles;
- overlap/quality checks;
- limited lags;
- Spearman as possible default;
- stability metadata;
- schema-level `causal: false`.

Brute-force all-pairs correlation mining запрещён.

## 13. Health State Snapshot

Point-in-time structure:

```text
conditions
medications
allergies
goals
metric states
recent events
conflicts
data quality
```

## 14. Health State Diff

Compares snapshots and detects:

- added/removed/changed structural state;
- new events;
- medication changes;
- metric changes;
- conflicts.

No LLM required.

## 15. What Changed?

```text
previous/current windows
→ State Diff
+ metric analytics
→ Change Candidates
→ Quality Filter
→ Meaningfulness Engine
→ Insight Candidates
→ Safety
→ optional AI explanation
```

Primary UX показывает 3–5 наиболее meaningful items, а не весь аналитический dump.

## 16. Meaningfulness

Input dimensions:

- magnitude;
- persistence;
- data quality;
- novelty;
- deviation from personal baseline;
- source reliability;
- user relevance;
- actionability.

Internal ranking допустим, но **не называется health risk score**.

Output uses reason codes, e.g.:

```text
persistent_change
outside_recent_personal_range
high_coverage
new_clinical_event
data_gap
```

## 17. InsightCandidate

До AI interpretation содержит только:

- type;
- subject;
- period;
- derived facts;
- reason codes;
- nearby events;
- quality.

Clinical interpretation отсутствует на этом уровне.

## 18. Analytics provenance

Каждый derived result хранит:

- algorithm;
- version;
- parameters;
- input record IDs;
- metric-definition version;
- calculated time.

При изменении inputs/algorithm mapping — stale → recompute.

## 19. Chart contract

Chart data различает:

- raw points;
- smoothed/derived line;
- personal baseline;
- reference range;
- clinical target;
- user goal;
- events/source transitions;
- missing periods.

Smoothed line никогда визуально не выдаётся за реальные measurements.

## 20. MVP metrics

Initial registry:

```text
sleep_duration
resting_heart_rate
steps
weight
hba1c
```

## 21. MVP algorithms

- coverage/freshness/source continuity;
- daily metric aggregation;
- rolling median baseline;
- MAD/IQR;
- absolute/relative delta;
- period comparison;
- sparse lab latest/previous;
- persistent shift;
- Health State Snapshot/Diff;
- rule-based meaningfulness;
- What Changed.

## 22. Acceptance principles

- two points never claim persistent trend;
- source transition can qualify/suppress insight;
- insufficient coverage suppresses strong conclusion;
- personal baseline never labelled clinical normal;
- analytics deterministic and reproducible;
- false-insight rate is first-class metric.
