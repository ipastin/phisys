# Tools, Connectors & MCP

## 1. Three boundaries

```text
Connector Boundary: external representation → SourceRecord
Domain Boundary: SourceRecord → Canonical Health Model
Agent Boundary: Canonical/Analytics → safe domain capability
```

Connector is never Agent tool directly.

## 2. Connector SDK

Common contract includes:

- capability discovery;
- authorization state;
- initial sync;
- incremental sync/cursor;
- deletions;
- revoke/disconnect where supported;
- source-schema version;
- typed errors.

Connector writes only Raw/Source layers.

## 3. Connector state

```text
NOT_CONFIGURED
AVAILABLE
AUTHORIZING
CONNECTED
SYNCING
PARTIAL_PERMISSION
REAUTH_REQUIRED
DEGRADED
ERROR
REVOKED
```

`CONNECTED` never implies complete data coverage.

## 4. Permission layers

```text
OS/provider permission
→ connector capability
→ internal agent/tool permission
```

Agent cannot automatically trigger broad OS permission request. UX explains why capability helps, then user initiates flow.

## 5. Health Connect — first real connector

Android first.

Logical modules:

- Health Connect fitness/wellness;
- Health Connect Medical Records later.

MVP data:

- Sleep;
- Steps;
- Heart Rate / Resting HR;
- Weight;
- optional Exercise where useful.

Progressive permission: do not request everything during onboarding.

## 6. Health Connect sync

Use source-native change tokens where available.

Store cursor per narrow record type/scope.

Invalid/expired cursor:

```text
bounded overlapping historical resync
→ idempotent ingestion
→ new cursor
```

## 7. Delivery semantics

Connector boundary uses **at-least-once delivery**. Ingestion is idempotent.

Source identity:

```text
connector_id + external_record_id
```

or fingerprint fallback.

Updates create new source/canonical version where semantics require, not garbage duplicates.

## 8. Deletion semantics

External deletion:

```text
source tombstone
→ check other supporting sources
→ update/invalidate canonical fact
→ dependent analytics/inference stale
```

Disconnect ≠ delete imported data.

## 9. Native Android bridge

React Native/Expo ↔ thin Kotlin module.

Responsibilities:

- availability;
- permissions;
- reads/changes;
- source metadata;
- serialization.

No terminology mapping, analytics or AI in native bridge.

## 10. HealthKit

Second native platform after MVP. Maps HealthKit anchors to common SyncCursor abstraction. Clinical records feed reusable FHIR adapter.

## 11. FHIR Adapter

Reusable independently of transport:

```text
FHIR resource
→ version detection
→ schema validation
→ normalizer
→ canonical mapper
```

First-class adapters planned for R4/R4B. R5 later.

## 12. SMART on FHIR

V1/V2 connector candidate.

Principles:

- standalone launch likely primary Personal Health use case;
- minimum necessary scopes;
- PKCE/OAuth handled in Auth/Connector layer;
- tokens never enter LLM context;
- offline access only if background sync requires it.

## 13. Document Connector

MVP supports text-based PDF lab reports.

Pipeline:

```text
upload
→ type/security validation
→ object storage
→ parser/layout
→ extraction candidates
→ terminology/unit validation
→ review ambiguous entries
→ canonical import
```

Original document remains available.

## 14. Manual Connector

Manual input uses same provenance/source pipeline as external sources. UI/Agent never bypass domain write path.

## 15. Direct wearable APIs

Not MVP. Add only for demonstrated gap such as provider-specific metric or metadata unavailable via Health Connect/HealthKit.

If both direct provider and platform aggregation exist, provenance/dedupe handles same-origin duplication.

## 16. Connector trust tiers

```text
T0 internal
T1 platform (Health Connect/HealthKit)
T2 verified provider
T3 user-supplied document/file
T4 untrusted external content
```

Trust tier does not equal clinical correctness; original device/app/provider metadata preserved when available.

## 17. Tool Gateway

Agent-facing tools grouped as:

### Health Read
- get_current_health_state;
- get_health_timeline;
- get_metric_series;
- get_current_medications;
- get_recent_symptoms;
- get_health_conflicts.

### Analytics
- get_metric_state;
- compare_metric_periods;
- what_changed.

### Evidence
- search_health_evidence;
- verify_evidence_claim.

### Workflow
- prepare_appointment_context (later).

Write tools are `propose_*`, not generic commits.

## 18. Tool schemas

Strict typed JSON in/out. Free-form query strings are avoided where structured arguments suffice.

Tools return quality/provenance metadata and never raw credentials.

## 19. MCP

MCP is **external protocol adapter**, not internal service bus.

MVP: no MCP.

V1/V2:

- read-only first;
- all requests pass Tool Gateway;
- least-privilege scopes;
- no raw DB/query/export-all tool;
- client/user/scope binding;
- output minimized.

## 20. Evidence provider

External evidence search is separate from personal health data. Query builder removes PII and unnecessary patient-specific values before external request.

## 21. Model provider

Models accessed only through Model Gateway. Connector/provider tokens and direct identifiers never included in model context.

## 22. Connector contract tests

Any production connector must test:

- availability;
- authorization;
- initial sync;
- incremental sync;
- update;
- delete;
- revocation;
- cursor expiry;
- duplicate delivery;
- network/rate-limit error;
- schema drift;
- quarantine.
