# Health Data Model

## 1. Strategy

Внутренняя модель **FHIR-independent, FHIR-compatible through adapters**.

FHIR R4/R4B — first-class interchange adapters. R5 может быть добавлен позже. Application code использует internal canonical identifiers, а не внешние terminology codes как primary keys.

## 2. Four data planes

### Raw
Неизменённый payload/source artifact. Immutable.

### Canonical
Нормализованные domain facts.

### Derived
Deterministic calculations, воспроизводимые без LLM.

### Inferred
AI-generated interpretations/hypotheses. Могут быть удалены/пересчитаны без изменения Clinical Store.

## 3. Required semantics for any health fact

Каждый persistent clinical object обязан отвечать:

```text
WHAT
WHO
WHEN
WHERE FROM
HOW VERIFIED
```

Минимум:

- person binding;
- concept;
- value/status;
- temporal semantics;
- source/provenance;
- epistemic status;
- verification status.

## 4. Epistemic model

```text
source_recorded
user_reported
normalized
calculated
inferred
disputed
unknown
```

Verification отдельно:

```text
source_verified
user_verified
system_verified
unverified
```

Нельзя смешивать epistemic type и confidence.

## 5. Core entities

### MVP

- Person;
- Observation;
- Symptom;
- Document;
- HealthEvent;
- Source;
- Provenance;
- Concept/Code/Unit;
- Conflict;
- DerivedMetric/Baseline.

### Near-term

- Condition;
- Medication;
- MedicationRegimen;
- MedicationIntake;
- Allergy;
- Encounter;
- Procedure;
- DiagnosticReport;
- Goal;
- Activity/Sleep/Nutrition domain views.

## 6. Observation

Observation поддерживает:

- numeric Quantity;
- coded value;
- string/boolean/range;
- reference ranges;
- specimen/body-site/method;
- point/period/date precision;
- source/provenance;
- status/versioning.

`concept` — structured reference:

```text
canonical_id
coding[]
original_text
```

Canonical key используется приложением; LOINC/SNOMED/etc — mappings.

## 7. Terminology

MVP terminology:

- internal Concept Registry;
- LOINC mappings для laboratory/observations;
- UCUM-compatible units.

Later:

- SNOMED CT;
- RxNorm;
- ICD;
- ATC.

Terminology Service централизован; fuzzy matching не размазывается по ingestion scripts.

## 8. Units

Сохраняются одновременно:

```text
original value + unit
canonical value + unit (optional)
conversion metadata
```

Conversion может зависеть от analyte/concept; запрещён universal `convertUnit(value, source, target)` для биохимических conversions без concept context.

## 9. Temporal model

Поддержать:

```text
Instant
Period
LocalDateTime
LocalDate
partial precision (year/month/day)
```

Нельзя превращать неизвестную дату `2022-03` в `2022-03-01 00:00`.

Отдельные timestamps:

```text
effective_at
recorded_at
ingested_at
```

## 10. Medication semantics

Не одна таблица `Medication`.

```text
Medication       what substance/product
MedicationRegimen prescribed/intended regimen over time
MedicationIntake actual intake event
```

`active: true` не является достаточной temporal model. Regimens versioned by effective periods.

## 11. Provenance

Provenance — first-class entity:

- source;
- original record ID;
- raw object reference;
- import method;
- transformation chain;
- imported time;
- verification.

Transformation chain versioned:

```text
PDF
→ text/layout parser vX
→ lab parser vY
→ terminology mapper vZ
→ unit normalizer vN
```

## 12. Document lineage

Любой extracted fact может ссылаться на:

- document;
- page;
- optional bounding box;
- text fragment/hash.

User UX должен позволять `View original` и по возможности подсвечивать relevant source location.

## 13. Versioning

Health history — append-mostly.

Correction:

```text
Record v1 (superseded)
→ Record v2 (current)
```

Старый факт не уничтожается молча.

## 14. Conflict model

Conflict — first-class state:

```text
value_conflict
status_conflict
date_conflict
source_conflict
identity_conflict
semantic_conflict
```

Система не обязана всегда выбрать одну «истину». `unresolved` является нормальным состоянием.

## 15. Duplicate vs conflict

Duplicate = несколько representations одного underlying event.

Conflict = разные claims об одном subject.

Identity resolution сохраняет relationship:

```text
Canonical Fact
├─ Source Representation A
├─ Source Representation B
└─ Source Representation C
```

## 16. Dedupe

Auto-merge только при высокой уверенности на основе:

- concept;
- timestamp;
- value;
- source/provider;
- specimen;
- external identifiers.

Thresholds являются engineering config и eval-calibrated, не hardcoded clinical truth.

## 17. HealthEvent

Unified timeline projection:

```text
observation
symptom
medication
medication_intake
condition
encounter
procedure
document
```

HealthEvent не дублирует full domain entity; это index/projection для Timeline, Context и State Diff.

## 18. Current Health State

Current state — deterministic projection over history:

```text
active conditions
current medications
active allergies
active goals
recent metrics
unresolved conflicts
```

Поддержать point-in-time snapshot `at`.

## 19. Data quality / missingness

Explicit states:

```text
complete / partial / unknown
exact / approximate
high / medium / low reliability
```

Rules:

- no measurement ≠ zero;
- no symptom entry ≠ no symptom;
- no medication intake ≠ missed dose.

## 20. Deletion/invalidation

Удаление source record должно:

1. tombstone source representation;
2. проверить другие supporting sources;
3. update/invalidate canonical fact при необходимости;
4. mark dependent Derived/Inference stale;
5. recompute search/insights.

## 21. MVP physical schema

Начать примерно с:

```text
persons
sources
raw_records
source_records
provenance
concepts
concept_codes
observations
symptoms
documents
document_links
health_events
conflicts
derived_metrics
baselines
```

Расширять вертикально после доказанного use case.
