# Health Skills Registry

## 1. Skill contract

Каждый skill обязан иметь:

```text
id + SemVer
purpose
when_to_use
when_not_to_use
inputs schema
outputs schema
permissions
allowed tools
max risk
execution type
failure policy
prompt (if any)
tests
evals
```

Skill source of truth = manifest + schemas + code + tests/evals. `SKILL.md` — human/agent documentation, но не единственная specification.

## 6. Example manifest — trend-analysis

```yaml
id: trend-analysis
version: 1.0.0
class: analytics
execution: deterministic
permissions:
  - observations.read
  - analytics.trend
allowed_tools:
  - get_metric_series
  - get_metric_state
risk:
  clinical_max: C1
  action_max: A0
llm_required: false
failure:
  insufficient_data: return_partial
```

## 7. Example manifest — lab-interpretation

```yaml
  - citations_for_medical_claims
  - uncertainty
  - no_diagnostic_conclusion

  schema: LabInterpretationResult
```

## 8. Skill — what-changed

### Input
- person;
- period;
- optional domains.

### Execution

```text
State Snapshot A/B
→ Diff
→ metric analytics
→ quality
→ meaningfulness
→ InsightCandidates
```

### LLM
Не требуется для core result. Optional `health-change-explanation` вызывается отдельным шагом.

### Key invariant
Skill не генерирует medical severity score.

## 9. Skill — record-symptom

### Flow

```text
user text
→ extract structured candidate
→ validate temporal/concept fields
→ preview
→ explicit confirmation
→ Manual Connector/domain write
```

### Forbidden
- direct canonical write from LLM;
- diagnosis inference;
- auto-saving user hypothesis as condition.

## 10. Skill — lab-interpretation

### Required inputs
- canonical lab observation;
- relevant history;
- source reference range if available;
- quality/provenance;
- approved external evidence.

### Output sections
- observed value/history;
- descriptive comparison;
- evidence-backed general explanation;
- uncertainty/missing context;
- questions/next useful step where appropriate.

### Forbidden
- inventing reference ranges;
- treatment change;
- unsupported diagnosis;
- arithmetic performed solely by LLM.

## 11. Skill release stages

```text
experimental
→ evaluated
→ trusted
→ production
```

New skill не попадает в planner registry до минимального eval gate.

## 12. Versioning

SemVer:

- Patch — implementation/prompt phrasing without contract change;
- Minor — compatible capability/optional input;
- Major — input/output/semantic change.

Historical execution trace всегда сохраняет skill version.

## 13. Skill file layout

```text
skills/<skill>/
  manifest.yaml
  SKILL.md
  input.schema.ts
  output.schema.ts
  execute.ts
  prompt/        # only if LLM-assisted
  tests/
  evals/
```

## 14. Skill Definition of Done

- typed input/output;
- narrow permissions;
- explicit risk;
- allowlisted tools;
- deterministic calculations delegated correctly;
- failure policy;
- unit tests;
- edge/missing/conflict evals;
- safety evals where C2+;
- documentation + changelog/ADR when semantics change.
