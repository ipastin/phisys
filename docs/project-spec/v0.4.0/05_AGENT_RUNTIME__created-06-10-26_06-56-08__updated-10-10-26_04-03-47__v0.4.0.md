# Agent Runtime

## 1. Runtime model

**Bounded hybrid, workflow-first.**

```text
Request
→ Intent + Risk
→ Route
   ├─ DIRECT
   ├─ SKILL
   ├─ COMPOSITE
   ├─ WRITE
   └─ SAFETY
→ Context/Tools as allowed
→ Claims
→ Verification
→ Policy
→ Response
```

Не используется open-ended autonomous loop.

## 2. Execution routes

### DIRECT
Точное retrieval. Planner не вызывается.

### SKILL
Предопределённый deterministic/LLM-assisted behaviour.

### COMPOSITE
Bounded DAG plan для сложных cross-domain requests. Не обязателен в first MVP.

### WRITE
Structured candidate → preview → confirmation → commit.

### SAFETY
High-risk flow bypasses normal planning.

## 3. Intent model

Base intents:

```text
retrieve
compare
trend
summarize
explain
investigate
correlate
record
update
prepare
plan
unknown
```

Domain классифицируется отдельно:

```text
observation
laboratory
medication
symptom
condition
sleep
activity
nutrition
encounter
document
general_health
```

## 4. Router output

Structured decision включает:

- route;
- intent;
- domain;
- entities;
- temporal scope;
- clinical/action risk;
- classifier confidence;
- optional skill.

Low confidence не расширяет tool/context scope автоматически.

## 5. Planner

Planner видит только:

- request;
- route/risk;
- available skill metadata;
- permissions;
- execution budget.

Output — DAG, не prose todo-list.

## 6. Hard budgets

Initial engineering limits:

```text
max plan steps = 8
max tool calls = 12
max retries/tool = 2
max replans = 1
max external evidence calls = 3
```

Values configurable/eval-driven, но unbounded execution запрещён.

## 7. Skill vs Tool

### Tool
Atomic approved capability:

```text
get_metric_series
get_current_medications
what_changed
```

### Skill
Product behaviour using tools:

```text
lab_interpretation
appointment_prep
record_symptom
```

## 8. Tool Gateway

Единственная execution boundary. Выполняет:

1. schema validation;
2. actor/client/permission check;
3. risk/policy check;
4. parameter-bound confirmation check;
5. execution;
6. output validation/sanitization;
7. audit metadata.

LLM не может grant permissions.

## 9. Tool restrictions

MVP Agent не получает:

```text
run_sql
shell_exec
arbitrary_http
filesystem_write
memory_write_any
modify_medication
send_external_message
```

Connector-specific tools также не выдаются Agent.

## 10. Context

Agent получает approved `HealthContextPackage`, а не full history.

Package включает only relevant:

- personal facts;
- derived metrics;
- conflicts;
- missing data;
- quality;
- provenance;
- external evidence when required.

## 11. Claim-first output

LLM-assisted reasoning генерирует typed claims:

```text
PERSONAL_FACT
CALCULATION
MEDICAL_FACT
ASSOCIATION
HYPOTHESIS
RECOMMENDATION
UNCERTAINTY
```

Final prose не считается source of truth.

## 12. Verification

### PERSONAL_FACT
Должен ссылаться на canonical record.

### CALCULATION
Должен ссылаться на DerivedMetric/algorithm.

### MEDICAL_FACT
Требует evidence по policy.

### ASSOCIATION
Не может автоматически повышаться до causal claim.

### Numeric claims
Пересчитываются deterministic verifier.

### Temporal claims
Проверяются against actual period.

## 13. Response Composer

Final response строится из approved claims.

Response patterns:

- Fact;
- Trend;
- Explanation;
- Investigation;
- Action/Preparation.

Safety boilerplate не добавляется к low-risk requests.

## 14. Permissions

```text
P0 READ
P1 ANALYZE
P2 DRAFT
P3 WRITE
P4 SENSITIVE
```

MVP P4 treatment actions отсутствуют.

## 15. Write approvals

Approval связан с:

```text
actor
specific tool/action
arguments hash
recipient/data scope if external
expiry
single-use
```

Изменение parameters требует нового approval.

## 16. Failure recovery

Skill manifest задаёт behaviour:

```text
missing_data → partial
connector_error → bounded retry
evidence_unavailable → omit interpretation
normalization_error → review/quarantine
```

Partial truthful answer предпочтительнее fabricated completeness.

## 17. Runtime state machine

```text
RECEIVED
→ CLASSIFIED
→ AUTHORIZED
→ ROUTED/PLANNED
→ EXECUTING
→ VERIFYING
→ SAFETY_CHECK
→ COMPOSING
→ COMPLETED
```

Failure states:

```text
BLOCKED
PARTIAL
FAILED
CANCELLED
```

## 18. Execution trace

Significant execution сохраняет metadata:

- route/risk;
- plan/skill versions;
- tool IDs/versions;
- context manifest ID;
- policy version;
- claim IDs/results;
- timing/errors.

Raw PHI/prompt не логируется по умолчанию.

## 19. MVP runtime scope

В первом release включить:

- DIRECT;
- SKILL;
- WRITE;
- SAFETY;
- COMPOSITE — feature-flagged/later.

Это сознательно снижает agentic surface.
