# UX & Product Interaction Architecture

## 1. Primary UX model

**Insight-first, not chat-first.**

```text
TODAY
→ WHAT CHANGED
→ EXPLORE
→ UNDERSTAND
→ ASK
→ RECORD / PREPARE / WATCH
```

The system should show trustworthy signal before AI interpretation.

## 1.1 Brand in UX

User-facing naming uses **MyPhisys**, not `Health AI`, `Phisys`, `Copilot` or a separate assistant persona.

- Product: **MyPhisys**
- Conversational entry: **Ask MyPhisys**
- Core feature: **What Changed**
- Do not use a separate AI character/name.
- Avoid `AI-powered`, `AI doctor`, `health score` and similar hype/authority language.

## 1.2 Surface architecture

The product uses four practical interaction roles:

```text
Full     → understand / investigate
Ambient  → glance / notice / capture
External → integrate / share
Voice    → input modality inside a trusted MyPhisys surface
```

Surface defaults:

- **Phone:** primary full experience;
- **Web:** deep-work companion;
- **Widget:** glance + deep link;
- **Watch:** glance + capture + handoff;
- **Push:** attention only, privacy-filtered;
- **MCP/API:** structured external interoperability.

A user should never need to interpret a complex health insight from a lock-screen notification or watch tile. Ambient surfaces hand off to the full authenticated surface for details, evidence, provenance and AI reasoning.

## 2. Mobile IA

Five primary destinations:

```text
Today
Timeline
Health
Records
Ask
```

Settings/Profile:

- Data & Connections;
- Privacy & Permissions;
- Memory & Personalization;
- Units & Display;
- AI & Sources;
- Notifications.

## 3. Today

Decision surface, not exhaustive dashboard.

Recommended sections:

1. What Changed;
2. Today metric summaries;
3. optional To Do / review items;
4. Upcoming appointments/workflows.

No generic Health Score in MVP.

## 4. What Changed

Primary summary groups:

```text
Meaningful changes
New
Stable
Data gaps
```

Stable explicitly distinguishes `nothing changed` from `we have no data`.

Primary view shows 3–5 items max. Full detail available deeper.

## 5. Insight Card

Hierarchy:

```text
metric
current state
change
a comparison basis
persistence/quality
Explore
```

AI paragraph is not primary card content.

Avoid red/green direction = good/bad semantics unless clinical policy justifies severity state.

## 6. Insight Detail

Order:

```text
FACTS
→ CHART
→ CHANGE START/PERSISTENCE
→ CONTEXT
→ DATA QUALITY
→ ASK MYPHISYS
```

Nearby event is described as context, never automatically effect/cause.

## 7. Metric Detail

Shows:

- current/latest value;
- personal baseline where valid;
- trend/delta;
- chart;
- events/source transitions;
- data quality/coverage;
- source;
- insight history.

Chart visually distinguishes raw, derived, baseline, reference, target, goal and missing periods.

## 8. Labs

Sparse lab UX uses `current / previous / delta / dates / source reference range`.

Two values → `lower/higher than previous`, not `persistent trend`.

## 9. Provenance UX

Two levels:

### Level 1
Simple source label and date.

### Level 2
Original document/source record, exact page/location, import method, transformation/calculation details.

`View original` is core trust feature.

## 10. Epistemic labels

Use when ambiguity matters:

```text
Medical record
User reported
Calculated
AI interpretation
```

Do not overload every screen with metadata.

## 11. Timeline

Unified chronological projection of clinical + behavioural events.

Dense sensor records are summarized into daily/domain events rather than hundreds of rows.

Filters:

```text
All
Clinical
Measurements
Medication
Symptoms
Lifestyle
```

## 12. Records

Canonical/source-oriented view:

```text
Labs
Medications
Conditions
Allergies
Visits
Procedures
Documents
```

Timeline answers `when`; Records answers `what is known about X`.

## 13. Conflict UX

`Needs review` is explicit actionable bucket.

Example medication conflict asks domain question (`Are you still taking it?`) instead of forcing user to choose FHIR vs conversation source.

`I'm not sure` must be available and preserve unresolved state.

## 14. Symptom/manual recording

Two entry modes:

- structured manual form;
- natural language.

Natural language always follows:

```text
extract
→ structured preview
→ edit/save
→ commit
```

No direct LLM write.

## 15. PDF import review

After extraction:

```text
Ready to import
Needs review
```

Only ambiguous fields require review. User should not inspect every correctly parsed row.

## 16. Ask MyPhisys landing

Global AI is cross-domain workspace, not blank-chat homepage.

Suggested prompts can come from current data but must avoid fear-inducing framing.

Example:

- Explore your recent sleep change;
- Explain latest lab results;
- What changed this month?;
- Prepare for appointment.

## 17. Scoped AI

`Ask MyPhisys about this` carries explicit subject/time/context scope.

Ask MyPhisys screen/header shows scope such as `Sleep · Sep 29–Oct 6`.

## 18. Context Inspector

User can inspect categories used:

```text
Using: Sleep 30d, Resting HR 30d, Medication changes 60d
Not using: unrelated categories
```

Default is `Auto · Minimum necessary`; advanced user may remove a category for a request.

## 19. AI answer anatomy

### Fact
Value + source.

### Explanation
Answer + Your Data + Evidence + Uncertainty.

### Investigation
What changed + same-period context + what can/cannot be concluded.

### Action-oriented
Summary + next useful step/questions.

Personal sources and external medical evidence displayed separately.

## 20. Uncertainty UX

Use semantic labels:

```text
Limited data
Records don't agree
Changed during the same period
Possible explanation
Based on available records
Data may be outdated
```

Do not show invented `87% confidence`.

## 21. Permission onboarding

Progressive and purpose-bound:

```text
Value explanation
→ data categories
→ OS permission
```

Do not ask 10+ Health Connect permissions at first launch.

## 22. Data Connections

Connection detail shows:

- state;
- enabled domains;
- last sync;
- coverage;
- issues;
- manage access;
- pause;
- disconnect.

`Delete imported data` is a separate destructive flow.

## 23. Error/degradation states

Specific states:

- source unavailable;
- analytics unavailable;
- AI unavailable;
- evidence unavailable;
- stale data;
- insufficient data.

Core data remains visible when AI unavailable.

## 24. Notifications

Conservative defaults. Insight ≠ notification.

Initial on/opt-in:

- sync failure: on;
- import complete: on;
- reminders: opt-in;
- weekly review: opt-in;
- meaningful change notification: opt-in;
- generic AI insight push: off.

## 24.1 Ambient privacy

Widget/watch/lock-screen content supports three privacy levels:

```text
Private   → "MyPhisys · 2 updates"
Balanced  → "2 health changes to review"
Detailed  → named metrics/values where explicitly allowed
```

Private/Balanced are the default for lock-screen-like contexts. A connected data category does not automatically imply permission to expose it on an ambient surface.

## 24.2 Cross-surface handoff

Canonical targets:

```text
Push/Widget change → Insight Detail
Widget Today       → Today
Watch Review later → Insight Detail on phone
Secure email link  → authenticated Web artifact
```

The receiving full surface must reconstruct the same insight ID/time range/source semantics, not generate an unrelated new interpretation.

## 25. Visual direction

`Clinical-neutral × consumer-readable × ultra-minimal`.

Avoid AI-slop:

- gradient hero cards;
- glowing orbs;
- sparkle icons;
- pseudo-scientific composite scores;
- anxiety-red everywhere;
- motivational filler.

UI should remain credible if all `AI` branding is removed.

## 26. MVP flows

### Flow A
Today → Sleep change → Explore → chart/context → Ask MyPhisys.

### Flow B
PDF upload → extraction review → Records → metric history → source/original → Explain.

### Flow C
Natural-language symptom → preview → confirm → Timeline.

These flows are product acceptance targets, not just prototypes.
