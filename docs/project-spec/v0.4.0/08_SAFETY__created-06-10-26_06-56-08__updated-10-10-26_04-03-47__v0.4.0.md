# Safety & Clinical Policy

## 1. Safety architecture

Safety is a **control plane**, not a system prompt.

```text
User request
→ minimal pre-safety classification
→ Policy Engine
→ authorized context/tools
→ execution
→ claim verification
→ clinical/privacy output policy
→ response/action
```

LLM находится между policy boundaries, но не определяет собственные permissions.

## 2. Multidimensional risk

Один severity number недостаточен. Используются оси:

```text
Clinical Risk     C0–C4
Action Risk       A0–A4
Data Sensitivity  D0–D4
Evidence Need     E0–E3
```

### Clinical Risk

- C0 retrieval;
- C1 descriptive analysis;
- C2 health interpretation;
- C3 bounded clinical reasoning;
- C4 treatment/time-critical safety flow.

### Action Risk

- A0 read;
- A1 local draft;
- A2 low-risk local write;
- A3 external/high-impact data action;
- A4 treatment consequence.

MVP: A4 unavailable.

### Evidence

- E0 none external required;
- E1 desirable;
- E2 required;
- E3 high-quality/current evidence mandatory.

## 3. Safety Decision

Policy output включает:

- disposition: allow / restricted / confirmation / redirect / deny;
- allowed skills;
- allowed tools;
- allowed context;
- prohibited actions;
- evidence/uncertainty/citation requirements.

## 4. Clinical boundary

Agent may:

```text
DESCRIBE
COMPARE
CONTEXTUALIZE
EXPLAIN
SURFACE EVIDENCE
GENERATE LABELED HYPOTHESES
PREPARE QUESTIONS
```

Agent does not autonomously:

```text
DIAGNOSE AS CONCLUSION
PRESCRIBE
START/STOP/CHANGE DOSE
OVERRIDE CLINICIAN ORDERS
DIRECT DEVICE/TREATMENT ACTION
```

## 5. Medication policy

Allowed:

- show recorded medication/regimen/history;
- explain recorded instructions/general evidence;
- prepare clinician questions.

Restricted:

- side-effect/interaction reasoning requires strong evidence and uncertainty.

Blocked executable actions:

- start/stop medication;
- dose change;
- replacement;
- prescription generation.

Drug interaction logic, if added, uses structured drug knowledge source first; LLM only explains.

## 6. Symptom policy

Symptom input path:

```text
structured extraction
→ safety screen
→ normal workflow OR restricted urgent flow
```

Production urgent routing must use clinically reviewed rules + classifier/defense-in-depth, not single LLM judgement.

## 7. Urgent flow

High-risk condition:

- stops ordinary planning;
- does not perform lengthy differential exploration first;
- prioritizes appropriate real-world action and concise explanation;
- localizes emergency/escalation UX where required.

## 8. Diagnosis semantics

`DIAGNOSTIC_CLAIM` cannot be emitted as established conclusion by consumer Personal Health Agent.

Allowed phrasing can express multiple possible explanations, but not convert `possible` into `you have X` without appropriate professional/validated product boundary.

## 9. Evidence policy

Claim requirements:

| Claim | Required support |
|---|---|
| personal measurement | canonical source |
| trend/delta | deterministic derived result |
| medication regimen | canonical source |
| general medical fact | credible external evidence |
| C3 clinical reasoning | high-quality evidence + uncertainty |
| treatment claim | restricted/blocked |
| hypothesis | labeled + supporting context |

Evidence tiers prefer regulators/guidelines/professional organizations → systematic reviews → peer-reviewed studies → reputable secondary sources.

## 10. Causality policy

Correlation/temporal overlap cannot be promoted to causality by LLM.

Causal language is classified at claim level. Unsupported `caused / because of / led to` claim is rejected or rewritten.

## 11. Recommendation taxonomy

```text
INFORMATIONAL
SELF_MANAGEMENT_LOW_RISK
CLINICIAN_DISCUSSION
TREATMENT
URGENT_ACTION
```

MVP autonomous TREATMENT recommendations are not available.

## 12. Prompt-injection boundary

All user text, PDF/EHR narrative, web and external tool output are untrusted data.

No external content can:

- change system policy;
- expand permissions;
- choose tools;
- write persistent memory directly;
- trigger arbitrary network action.

## 13. External sharing

Any health-data export/share is A3 minimum and requires:

- recipient/destination;
- exact data scope;
- preview;
- explicit parameter-bound approval;
- audit.

Disconnect/pause/delete remain separate actions.

## 14. Fail-safe behaviour

Consequential action fails closed if authorization/policy/approval unavailable.

Read-only UX can degrade gracefully.

Degradation modes:

```text
NORMAL
LIMITED
READ_ONLY
SAFE_RESPONSE_ONLY
UNAVAILABLE
```

## 15. Claim-first output policy

LLM produces structured candidate claims → verification → safety policy → approved claims → response composer.

Final prose is not trusted until claims pass policy.

## 16. Privacy policy

Safety control plane includes privacy rules:

- purpose limitation;
- minimum necessary context;
- sensitive-compartment isolation;
- provider data policy;
- retention/deletion;
- external-query de-identification.

Direct identifiers normally stripped before model/evidence calls.

## 17. Regulatory intent metadata

Each feature declares intent such as:

```text
record_management
general_wellness
education
clinical_information
clinical_decision_support
diagnostic
treatment
```

MVP intentionally avoids treatment/diagnostic intended use.

## 18. Safety metrics

- Unsafe Clinical Claim Rate;
- Unsupported Diagnostic Claim Rate;
- Treatment Directive Rate;
- False/Missed Urgent Flow Rate;
- Causal Overclaim Rate;
- Citation Support Rate;
- Permission Violation Rate;
- Sensitive Context Exposure Rate;
- Approval Bypass Rate;
- Prompt Injection Success Rate;
- Over-refusal Rate.

Safety оценивается вместе с task usefulness; отвечать «обратитесь к врачу» на всё — failure product quality.

## 19. Kill switches

Feature flags must allow rapid disable for:

- agent;
- write tools;
- external sharing;
- model provider;
- individual skill;
- connector.

## 20. MVP safety gate

Personal Beta blocked if:

- critical authorization bypass > 0;
- treatment-modification capability exposed;
- critical prompt injection succeeds;
- RLS isolation fails;
- numeric verifier fails golden cases;
- sensitive unrelated context can leak into model request.
