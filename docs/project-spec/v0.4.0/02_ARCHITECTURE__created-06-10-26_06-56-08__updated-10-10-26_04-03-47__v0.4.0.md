# System Architecture

## 1. Target architecture

```text
External Sources
    ↓
Connectors
    ↓
Raw / Source Store
    ↓
Normalization + Identity + Dedupe
    ↓
Canonical Health Store
    ↓
State Resolver + Analytics
    ↓
Insight Candidates
    ↓
Safety pre-policy
    ↓
Context Engine
    ↓
Skills / Agent Runtime
    ↓
Claim Verification + Output Policy
    ↓
UX
```

Поперечные planes:

```text
Auth · Privacy · Provenance · Audit · Observability · Evals
```

## 2. System style

**Modular monolith + independent workers + Ports & Adapters.**

MVP не использует microservices, Kubernetes, Kafka, graph DB или отдельный vector DB.

### Runtime processes

```text
Mobile ─┐
Web ────┼─→ Fastify API → PostgreSQL
        │                 ↕
        │               Worker
        │                 ↕
        └────────────── Object Storage

API/Worker → Model Gateway → approved model provider
API/Worker → Evidence Provider (de-identified query only)
```

## 2.1 Delivery / surface architecture

UI delivery is a separate plane over the same MyPhisys Core:

```text
                         MyPhisys Core
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   FULL SURFACES        AMBIENT SURFACES      EXTERNAL SURFACES
   Mobile / Web         Widget / Watch        MCP / API
                        Push / Quick Add       FHIR / Secure Share
```

Rules:

- Android mobile is the Personal Beta primary health acquisition + trusted interaction surface;
- Web is a deep-work companion and never fakes native Health Connect/HealthKit acquisition;
- ambient surfaces expose privacy-filtered glance/notice/capture capabilities only;
- complex reasoning and provenance resolve to a trusted full surface through deep links;
- external surfaces always pass through the same Tool Gateway / Safety / Context / Privacy control planes;
- surface capability contracts define role, data scope, action scope and privacy mode;
- feature parity is not an architectural requirement.

See `17 SURFACE_STRATEGY`.

## 3. Module boundaries

### `health-core`
FHIR/vendor-independent domain entities и invariants.

### `ingestion`
SourceRecord → validation → mapping → canonical facts.

### `clinical-state`
Point-in-time Health State Snapshot и current projection.

### `analytics`
Quality, baseline, trend, diff, meaningfulness.

### `context-engine`
Minimum-necessary context assembly.

### `memory`
Typed non-clinical memory/candidates; Clinical Memory = Canonical Store.

### `safety`
Clinical/action/data/evidence policy, authorization requirements, output rules.

### `tool-gateway`
Единственная execution boundary для Agent tools.

### `skills`
Typed product behaviours, использующие domain tools.

### `agent-runtime`
Router → bounded planner → executor → claims → verifier → composer.

### `model-gateway`
Provider-independent inference boundary. Owns capability aliases, provider eligibility, privacy/risk routing, de-identification, structured outputs, model budgets, fallback and model telemetry. Skills never import provider SDKs or model IDs.

Initial Personal Beta deployment:

```text
classifier_fast      → GPT-6 Luna
extractor_text       → GPT-6 Luna
extractor_vision     → GPT-6.1 Sol
reasoning_standard   → GPT-6.1 Sol
reasoning_high       → GPT-6 Astra
summarizer           → GPT-6 Luna
claim_reviewer       → GPT-6.1 Sol
```

This mapping is replaceable configuration and must pass MyPhisys capability-specific evals.

### `evidence`
External medical evidence, отделённое от personal health data.

## 3.1 Model execution architecture

```text
Request
  ↓
Safety / task classification
  ↓
Context requirements
  ↓
Context Engine
  ↓
Privacy Filter (P0–P3)
  ↓
Logical Model Capability
  ↓
Provider Eligibility
  ↓
Model Gateway
  ↓
Structured Output / Claims
  ↓
Verification + Output Policy
```

Rules:

- model selection occurs only after context/privacy authorization;
- provider fallback must have equal or stronger privacy guarantees;
- provider-native memory is not MyPhisys memory;
- provider-hosted medical-file storage is disabled by default;
- large context windows never relax minimum-necessary context policy;
- no eligible provider results in graceful degradation, not privacy downgrade;
- numerical/temporal truth remains deterministic.

See `16 MODEL_STRATEGY` for the full provider and deployment policy.

## 4. Data planes

```text
RAW        original evidence
CANONICAL  normalized domain facts
DERIVED    deterministic calculations
INFERRED   AI interpretations/hypotheses
```

Ни один plane не может silently masquerade as другой.

## 5. Trust boundaries

### Trusted control plane
- system policy;
- code-defined skill manifests;
- tool schemas;
- authorization decisions;
- deterministic algorithms.

### Untrusted data plane
- user text;
- PDF/EHR narrative;
- web/evidence content;
- tool outputs from external systems;
- connector metadata.

Untrusted content является **data, never instructions**.

## 6. Source independence

Agent работает только с source-independent tools:

```text
get_metric_series
get_current_medications
what_changed
get_health_timeline
```

Запрещено давать Agent tools вида:

```text
health_connect_get_steps
fhir_query
run_sql
http_fetch
```

Connectors существуют ниже domain boundary.

## 7. Core runtime paths

### Simple retrieval

```text
request
→ router
→ domain tool
→ verified response
```

### Deterministic skill

```text
request
→ skill
→ read tool
→ deterministic analytics
→ response
```

### Composite reasoning

```text
request
→ safety pre-policy
→ bounded planner
→ approved skills/tools
→ context package
→ structured claims
→ verification
→ output policy
→ response
```

### Write

```text
natural language
→ structured candidate
→ validation
→ preview
→ parameter-bound confirmation
→ domain commit
→ audit
```

### Urgent/high-risk

```text
request
→ pre-safety
→ restricted safety flow
```

Обычный planner не выполняется.

## 8. Failure domains

### Model unavailable
Работают Records, Timeline, Metric Detail, analytics, What Changed.

### Worker unavailable
Чтение существующих данных работает; sync/recompute задерживаются.

### Connector unavailable
Существующая история доступна; новые данные не синхронизируются.

### Evidence unavailable
Personal analytics доступны; C2/C3 interpretation ограничивается.

## 9. Dependency rules

- `health-core` не импортирует model/vendor/UI/infrastructure SDK.
- `connectors` не импортируют analytics/agent packages.
- `analytics` не пишет Raw/Canonical data.
- `agent-runtime` не имеет direct database implementation.
- `skills` не импортируют model provider SDK и не содержат production model IDs.
- `model-gateway` не становится source of health truth.
- application/domain code requests logical capabilities (`reasoning_high`, `extractor_vision`, etc.), not named models.
- provider fallback cannot weaken retention/privacy/compliance requirements.
- `evidence` не пишет в Canonical Health Store.
- client не определяет canonical semantics.

## 10. Persistence architecture

PostgreSQL schemas:

```text
identity
source
health
analytics
memory
agent
evidence
audit
jobs
```

Object storage:

- original documents;
- source artifacts;
- exports.

pgvector:

- documents;
- conversation retrieval;
- evidence retrieval;
- никогда не current clinical state.

## 11. Asynchronous architecture

Background work через PostgreSQL-backed queue (initially pg-boss) + transactional outbox.

Typical events:

```text
source.record.created
health.observation.created
health.medication.changed
analytics.metric.invalidated
conflict.detected
document.imported
```

Jobs idempotent.

## 12. Architectural invariants

Сокращённый critical list:

1. LLM cannot write Clinical Store directly.
2. Connector cannot write Derived/Inference.
3. Every persistent clinical fact has provenance.
4. Analytics are reproducible from inputs + algorithm version.
5. Missing ≠ negative/zero/normal.
6. Current Health State is projection over history.
7. AI inference remains separate from fact.
8. Authorization happens outside model.
9. Final substantive clinical prose is composed from verified/policy-approved claims.
10. Personal health queries are de-identified before external evidence search.
11. Credentials never enter model context.
12. Core product remains useful without LLM.

Полный журнал решений — `13 ADR`.
