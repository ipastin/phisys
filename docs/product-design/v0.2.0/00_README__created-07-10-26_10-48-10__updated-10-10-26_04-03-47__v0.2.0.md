# MyPhisys Product Design Specification Pack

## 1. Purpose

Этот пакет — **source of truth для продуктового дизайна MyPhisys в Figma**. Он переводит продуктовую, data, analytics, agent и safety-архитектуру в конкретные проектные решения: information architecture, screen map, user flows, wireframe blueprints, screen specifications, states, components, design tokens, charts, AI interactions, privacy/permissions, content design, accessibility, cross-surface delivery и handoff.

Пакет рассчитан на Senior Product Designer: он не объясняет основы UX/UI, а фиксирует **решения, rationale, trade-offs, edge cases и acceptance criteria**.

## 2. Design thesis

**MyPhisys — insight-first Personal Health Intelligence product, не chat-first AI assistant и не quantified-self dashboard.**

Основной interaction loop:

```text
Today
→ What Changed
→ Explore
→ Understand
→ Ask MyPhisys
→ Record / Prepare / Watch
```

Порядок доверия в интерфейсе:

```text
Facts
→ Calculation / comparison
→ Context
→ Interpretation
→ Suggested next action
```

AI не должен визуально или семантически занимать место source of truth.

## 6. Scope notation

Every screen/spec is tagged:

- **MVP** — required for Personal Beta v0.1;
- **V1** — next release candidate;
- **V2** — future exploration;
- **Platform** — OS/system-owned surface, documented only for transition/context.

## 7. Design decision hierarchy

When docs conflict, use this order:

1. safety/privacy invariant;
2. health-data semantics/provenance;
3. product principle;
4. screen specification;
5. design-system rule;
6. local visual decision.

Do **not** fix a semantic problem with visual styling.

## 8. Product-wide invariants for design

1. **Facts before interpretation.** AI explanation never precedes the data it interprets.
2. **Unknown stays unknown.** Missing, insufficient, stale and conflicting are distinct states.
3. **Personal baseline ≠ clinical normal.** Copy and visual encoding must preserve the distinction.
4. **Direction ≠ judgement.** Increase/decrease are not automatically good/bad.
5. **Source is reachable.** Consequential facts and calculations can be traced.
6. **AI is inspectable.** User can understand what context/sources were used.
7. **Write actions are previewable.** Natural language → structured preview → confirmation.
8. **Calm by default.** Warning treatments are reserved for actual safety/policy states.
9. **Stable is informative.** Product must not create anxiety by only surfacing changes.
10. **Core value survives without AI.** Today, Timeline, Records, charts and What Changed remain useful if AI is unavailable.

## 9. Figma working principle

Design in three explicit layers:

```text
Layer A — semantics
content hierarchy, objects, states, interaction rules

Layer B — structure
layout, density, responsive behavior, components

Layer C — visual language
color, type, shape, motion, illustration
```

Do not start brand-polish before Layer A/B has passed usability review.

## 11. Open decisions that should remain open in Figma exploration

- final visual identity/colors/typeface;
- exact mobile chart interaction (scrub vs tap/crosshair hybrid);
- whether `Health` top-level domain index is needed in the first MVP build or can be progressive;
- density of Today metric summaries below What Changed;
- placement of global `Ask MyPhisys` affordance on mobile beyond bottom-nav entry;
- whether desktop AI uses fixed side panel or resizable workspace.

These should be tested, not silently frozen by this document.
