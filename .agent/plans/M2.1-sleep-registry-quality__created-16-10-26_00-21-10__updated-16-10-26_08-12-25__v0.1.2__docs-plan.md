## 4. Scope / Non-goals

One synthetic device-derived `sleep_duration` metric, canonical hours and local-date daily coverage. Query current facts and active Raw provenance; expose coverage, missing dates, freshness, source continuity, uncertainty and `duplicateReceiptCount: unavailable`. The revised Quality policy 1.0.1 accepts an explicitly recorded daily quantity from 0 through 25 hours inclusive, excluding out-of-range values from samples. This is an engineering data-validity bound, not a clinical threshold, target or risk score. No baseline/trend calculation, state snapshot/diff, meaningfulness, What Changed, UI, LLM, real records, production auth, cloud or deploy.

## 5. Invariants / Architecture impact

Person ID is required as UUIDv7; a dedicated NOLOGIN analytics role gets column-level SELECT, RLS by `app.person_id`, and a `READ ONLY` transaction. Raw payload remains inaccessible. Only current local-date canonical facts enter the DB query. The pure evaluator ignores valid dated facts outside its requested window before counting or collecting provenance; undated or invalid-calendar inputs remain exclusions. Missing provenance, unresolved conflicts and invalid values are excluded by Quality with explicit reasons. Missing days are unknown, not zero; a recorded 0 h remains a distinct observation. The versioned registry, nested policy and returned parameter snapshot are frozen to preserve reproducibility. Unverified facts cannot yield `sufficient`. A connector switch is flagged without claiming method compatibility. Existing canonical model and accepted ADR are unchanged.

## 10. Decision log

16-10-26: chose the PR #6 recommended one-metric vertical slice. Alternative broader five-metric coverage would require unsupported clinical mapping and sparse fixtures; alternatively a bare registry without DB evidence would not prove the M1 boundary. Chose the plan's dedicated role over transaction-only read-only access because column grants and RLS can be tested independently; the role is limited to required provenance columns. Owner's M2.1 instruction authorizes this slice, not any canonical, clinical, safety/privacy or UX change.

16-10-26 review fix: selected 0–25 h inclusive for one local-date daily observation. A strict 24 h cap could reject a one-hour fall-back day; leaving only the M1 finite-number check permits physically impossible 1000 h values. Without source timezone the precise day length cannot be calculated, so 25 h is a conservative synthetic Quality bound pending a richer temporal contract. Zero is accepted only when a source explicitly recorded it, never inferred from missingness. Version 1.0.1 records the changed policy. Chose runtime freezing plus a frozen per-result parameter snapshot over documentation-only immutability because callers can otherwise change later results without a version change.

## 11. Surprises / Open questions

M1 deduplicates exact retries before creating Raw records, so receipt volume is unavailable. Connector IDs show a source transition but do not establish measurement-method equivalence. Historical knowledge-as-of is unavailable from current-state M1 facts. Production caller identity resolution requires a later auth decision. The 25 h bound may need timezone-aware refinement if M1 later carries source zone/interval data; this review fix does not change Canonical validation. A direct package-level unit command still assumes built workspace dependencies; root `pnpm test` and CI use Turbo's build dependency.
