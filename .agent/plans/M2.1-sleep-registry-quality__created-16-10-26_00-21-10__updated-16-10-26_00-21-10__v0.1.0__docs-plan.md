# M2.1 — synthetic sleep duration, Steps 08–09

## 1. Goal / Why

Read current M1 `sleep_duration` facts for one person through a DB-enforced read-only boundary. Return a versioned metric definition and deterministic Quality result before any baseline, trend or insight can use those facts.

## 2. Status / Authorization

`in_progress`; owner approved Steps 08–09 in the 16-10-26 request against [M2 ExecPlan PR #6](https://github.com/ipastin/phisys/pull/6). Code commit: `a342437b47cdd2f1024fe56f5cf018465c9c0c72`. Review PR is pending; merge and deploy have no authorization.

PR #6 is the approved scope source, still outside main; source packs were read-only.

## 4. Scope / Non-goals

One synthetic device-derived `sleep_duration` metric, canonical hours and local-date daily coverage. Query current facts and active Raw provenance; expose coverage, missing dates, freshness, source continuity, uncertainty and `duplicateReceiptCount: unavailable`. No baseline/trend calculation, state snapshot/diff, meaningfulness, What Changed, UI, LLM, clinical threshold, health risk score, real records, production auth, cloud or deploy.

## 5. Invariants / Architecture impact

Person ID is required as UUIDv7; a dedicated NOLOGIN analytics role gets column-level SELECT, RLS by `app.person_id`, and a `READ ONLY` transaction. Raw payload remains inaccessible. Only current local-date canonical facts enter the query; missing provenance, unresolved conflicts and invalid values are excluded by Quality with explicit reasons. Missing days are unknown, not zero. Unverified facts cannot yield `sufficient`. A connector switch is flagged without claiming method compatibility. Existing canonical model and accepted ADR are unchanged.

## 6. Files and dependencies

- `packages/database/migrations/0002_{up,down}.sql`: analytics role, SELECT grants and RLS; `src/migrate.ts`: M1→M2/idempotent application; `src/analytics.ts` and `src/index.ts`: scoped query/export.
- `packages/analytics/src/index.ts`: registry and pure Quality calculation; `package.json`, `tsconfig.json`, root `package.json` and `pnpm-lock.yaml`: workspace build/test wiring.
- `packages/analytics/test/{quality,integration}.test.ts` and `packages/database/test/integration.test.ts`: synthetic golden and DB behavior. M1 `packages/ingestion/test/golden.ts` is reused without edits. Callers: new `sleepQuality(pool, personId, window)`; no existing callers changed.

## 10. Decision log

16-10-26: chose the PR #6 recommended one-metric vertical slice. Alternative broader five-metric coverage would require unsupported clinical mapping and sparse fixtures; alternatively a bare registry without DB evidence would not prove the M1 boundary. Chose the plan's dedicated role over transaction-only read-only access because column grants and RLS can be tested independently; the role is limited to required provenance columns. Owner's M2.1 instruction authorizes this slice, not any canonical, clinical, safety/privacy or UX change.

## 11. Surprises / Open questions

M1 deduplicates exact retries before creating Raw records, so receipt volume is unavailable. Connector IDs show a source transition but do not establish measurement-method equivalence. Historical knowledge-as-of is unavailable from current-state M1 facts. Production caller identity resolution requires a later auth decision. No new owner decision is required to review this narrow PR.

## 12. Recovery / Idempotence

Run `migrate:up` again safely: schema sentinels skip applied 0001/0002 migrations. On a disposable DB only, `M1_DISPOSABLE_DB=1 pnpm --filter @myphisys/database migrate:down` reverses 0002 then 0001; the cluster-wide NOLOGIN analytics role is retained without grants. The migration runner needs a ledger before partial/concurrent upgrades become a supported scenario. No source pack or main content changed.
