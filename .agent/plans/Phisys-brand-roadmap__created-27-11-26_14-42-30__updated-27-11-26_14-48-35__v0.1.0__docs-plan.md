# Единое имя и карта разработки

## Решение и границы

27 ноября 2026 владелец утвердил название Phisys для всего проекта и запросил полную карту разработки и оценку готовности UX/UI Android и Web. Исходная точка — [main после PR #17](https://github.com/ipastin/phisys/commit/3679cc0e206c5b6e8ec6e56f0c696e25a6121663). [Draft PR #18](https://github.com/ipastin/phisys/pull/18) имеет отдельный scope. Merge, развёртывание и работа с живыми данными требуют отдельного решения.

## Выполнение и зависимости

1. Проверить PR и реализацию, взять шаги 00–39 из Implementation Blueprint и порядок платформ из Surface Strategy.
2. Выпустить Project Spec 0.4.1 и Product Design Spec 0.2.1, обновить инструкции, индексы, примеры, workspace packages, импорты, lockfile и CI. Оригиналы опубликованных спецификаций и точные исторические команды доступны в Git по исходному commit. В обновлённых планах имена пакетов приведены к текущему написанию.
3. Для новых установок PostgreSQL использовать текущие названия ролей. При обработке уже созданных баз сохранить действующие права, политики изоляции и доступ существующих callers. PostgreSQL роли общие для всего кластера.
4. Проверить все шаги карты, ссылки, manifest, написание бренда, frozen install, сборку, тесты и CI. Для сценария PostgreSQL использовать только временную синтетическую БД.

## Приёмка и восстановление

Доступность прежних исходных пакетов проверяется по зафиксированному commit, ссылки текущих документов — по дереву PR. Карта показывает частичные шаги аналитики сна и отделяет draft от main. Исходные продуктовые решения о платформах, данных и клинической семантике сохраняются. При откате Git возвращает прежние пакеты документации и кода. Права существующих баз не требуют отката глобального переименования ролей.


## Проверки рабочего дерева

27 ноября, cwd — корень репозитория, изменения поверх `3679cc0`. На рабочем дереве прошли `pnpm install --frozen-lockfile`, lint, format, typecheck, build, unit и 19 architecture tests. Все 29 PostgreSQL integration tests прошли на временной версии 16. Отдельный прогон CLI подтвердил сосуществование новой и прежней базы в одном кластере. Доступ старой базы определяется её действующей RLS policy.

В сборке оба manifests перечисляют 18 и 28 документов. Редактируемая карта покрывает все 40 шагов и S0–S5. PR #18 потребуется согласовать с новым package scope и выбрать имя создаваемой им роли до включения в main. Если этот PR будет объединён первым, перед merge изменения бренда нужно проверить поверх новой базы ветки. Результаты CI доступны в проверках PR.
